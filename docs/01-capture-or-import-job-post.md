# Step 1: Capture Or Import A Job Post

## Purpose

This step turns a job posting into a persisted, normalized `CapturedJob` that the desktop app can review. It has three entry paths:

- The browser extension posts the current page's extracted payload to `POST http://127.0.0.1:3000/captures`.
- The desktop app imports a URL through the `import_job_from_url` Tauri command.
- The desktop app extracts pasted posting text through `import_job_from_text`.

Every successful path converges at `server::persist_capture`. Capture is deliberately storage-only: it must not start ATS analysis, evidence preflight, tailoring, or document generation. The user reviews the normalized result before an AI analysis call is made.

## Data Flow

### Browser extension capture

The Manifest V3 extension opens the popup, sends an extraction request to its content scripts, and posts the extracted JSON to the local bridge. The usual payload includes a title, company, description, source URL, and board-specific metadata. The extension is best-effort; it has no quality threshold, so an incomplete extraction is still stored and surfaced for review.

`POST /captures` calls `persist_capture`, emits `job-data-received` to the Tauri window, and returns a success response containing the parsed job and timestamped capture path. The route does not invoke the legacy `/analyze` flow.

### URL import

`import_job_from_url` delegates to `job_import::import_from_url`.

1. The URL is normalized and fetched with the shared HTTP client and a short page-fetch timeout.
2. The importer first looks for a usable schema.org `JobPosting` in JSON-LD. This is local parsing and does not consume model tokens.
3. Without usable JSON-LD, page HTML is converted to block text. Pages that are too short, blocked, missing, non-HTML, or client-rendered return an actionable error that directs the user to paste the posting text.
4. Usable page text is sent to the extraction model, which returns the normalized `ExtractedJob` shape.

### Pasted-text import

`import_job_from_text` delegates to `job_import::import_from_text`. Pasted text always uses the extraction model because there is no JSON-LD markup to inspect. A pasted optional source URL is only used as a display/source link; an invalid optional URL does not make the import fail. HTML-looking pasted text is reduced to block text before extraction.

Both imported paths build the same capture payload shape as an extension capture, persist it, and emit `job-data-received`. The React import panel intentionally ignores the command's returned capture: the event listener owns the complete state reset for a new job.

## Persistence And Normalization

`CapturedJob` has three fields:

- `received_at_ms`: unique capture timestamp and the identity used to reject stale UI events/results.
- `payload`: original incoming payload, retained for capture debugging.
- `parsed`: normalized board-agnostic job data used by the UI and later AI stages.

`persist_capture` writes an immutable timestamped file at `data/job-captures/<timestamp>-job.json`, then atomically updates `data/job-captures/latest.json`. The latter is the pointer loaded when the desktop app starts; replacing it starts work on a new job without deleting capture history.

`parse_job_data` selects a parser by the payload's `source` discriminator before examining the URL. This is important for imports: an imported payload may reference a supported board but was not generated by that board's scraper. Imported data normalizes from its own `json` field instead.

## Privacy And Prompt Boundary

For an AI-extracted import, `payload.sourceText` retains raw fetched or pasted text for debugging. It must never reach an AI prompt. The imported `parsed` object contains normalized fields only; the import route must not add `parsed["raw"]`.

All later callers use `server::prompt_job_view(parsed)`, which drops debugging, duplicate, and irrelevant fields such as `sourceText`, `raw`, and `description_html`. Preserve this boundary whenever capture formats or parsers change.

## Failure Behavior

- A browser extension failure remains in the extension UI; no capture is written.
- A thin or warning-bearing capture still reaches review, where the re-import panel opens by default.
- URL import errors identify the expected workaround: use the posting page in a browser and paste its text.
- If an import persists successfully but the desktop event cannot be emitted, the command reports that the job was imported but cannot be displayed until restart. Do not silently treat this as a normal success.
- Import cancellation only stops the panel's waiting state. An already-sent request can still complete, persist, and emit its capture event.

## Files And Ownership

- `browser-extension/manifest.json`, `popup/popup.js`, `background/background.js`, and `content-scripts/`: browser-side extraction and delivery to `/captures`.
- `src/job-import.tsx`: URL/paste import UI, validation, busy/cancel state, and command invocation.
- `src-tauri/src/job_import.rs`: URL fetching, JSON-LD parsing, text cleanup, model extraction, import payload construction, and import-specific errors.
- `src-tauri/src/server.rs`: capture parser selection, normalized `CapturedJob`, disk persistence, `/captures`, and prompt-safe job view.
- `src-tauri/src/commands.rs`: import Tauri commands and `finish_import`, which persists and emits the common capture event.
- `src/main.tsx`: `job-data-received` listener and `resetForCapture`, which clear all state belonging to the preceding job.

## Relevant Tests

- `src/job-import.test.tsx` verifies both import command payloads and panel behavior.
- `src/workflow.test.tsx` covers capture-event reset/deduplication, thin-capture re-import disclosure, and review-after-import behavior.
- `src-tauri/src/job_import.rs` tests cover URL normalization, JSON-LD extraction, text thresholds, and import error cases.
- `src-tauri/src/server.rs` tests cover capture parsing, persistence helpers, and prompt-view exclusion of raw data.
